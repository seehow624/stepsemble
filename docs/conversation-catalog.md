# Unified conversation catalog (Plan 1.48)

3.0.7-rc.5 development candidate. Production remains 3.0.6; the frozen rc.1
72-hour soak does not test this code. No native model, credential, routing,
production restart or private source registration is part of this change.

## Delivered scope

The Sessions heading's **All conversations** button opens a native modal with
the currently selected Host's visible Pi session summaries and Stepsemble's
existing multi-agent task records. It uses the existing authenticated endpoints,
not a second filesystem scanner or a new permission grant. The established
Claude read-only history entry remains separate and retains its per-credential
catalog authorization; those labels are not copied into the legacy Host-wide list.

- `client/conversation-catalog.ts` supplies a strict TS metadata index and view;
  its checked-in JS is generated by the existing pinned client build.
- Identity is the tuple Host, record kind, exact source reference. Same title,
  cwd, model or native-looking ID across different sources never merges records.
- Only a Pi task whose exact file matches a visible Pi history is deduplicated.
  Native history title/status wins over the transient process task's title/exit.
  Duplicate ambiguous references within a source are omitted, not first/last-wins.
- Native Pi names retain their existing user-title/first-user-message fallback;
  no filename or assistant response is invented as a native title. Display text
  is capped at 500 UTF-16 units; reference is at most 4096. Raw metadata is not changed.
- Unknown sources have the neutral local mark and unknown statuses stay unknown.
  A task output label is not complete history, an approval or a resume capability.
- Search is local metadata search, not a hidden full-transcript scan. At most
  10,000 Pi rows + 256 tasks enter the index, and only 50 rows enter the DOM per
  page. The omitted count and visible source limitations are explicit.
- Existing subagent visibility preferences determine which Pi summaries reach
  the view; the catalog does not silently enable hidden native history discovery.
- Native modal focus containment, Escape, keyboard shortcut isolation, 44px
  targets, fixed pages and an independently scrolling list follow Apple Design
  principles without new animation or runtime dependencies.
- Background polls do not reorder this snapshot under a focused row. Explicit
  refresh reuses same-key row DOM; source failures preserve last-known records
  and add a stale notice. Host switch/logout clears and closes the view. Click
  resolves against the current Host's actual source list rather than a saved URL.

The client also fences `/api/rpcs` polls by Host/view, coalesces a slow current
flight, aborts on scope reset and ignores malformed/late data. Session-summary
refresh no longer treats a missing/non-array `sessions` field as a valid empty store.

## Generic task input and stream corrections

Completed, failed, stopped, orphaned and detached task views now show a
read-only notice and block Send before clearing drafts or adding a false user
message. Running/waiting inputs require the current stream's validated
`connected` snapshot, not merely the EventSource `open` event. Unknown,
starting/reconnecting, transport-lost and stop-pending states retain drafts
without sending. These are UI readiness checks, not new native capabilities;
the Host's existing task-state checks remain authoritative.

Callbacks/timers are fenced by exact RPC object, Host, view generation and
EventSource. A foreign/malformed connected frame cannot enable input. Historical
lifecycle events at/before the connected sequence cannot overwrite its current
task state, while historical output is still displayed. Terminal EOF explicitly
closes EventSource, preventing its default repeated reconnection to a completed
record. No native session resume or subscription/account mutation is added.

## Verification

- Local full suite: 667 cases, 665 passed, two platform-specific skips, zero
  failures. Syntax, generated client, version consistency and protocol checks pass.
- Unit cases: same-name isolation, Pi task/history deduplication, name fallback,
  unknown source non-authority, ambiguity/malformed input, detached bounds,
  filters/temporary records, fixed paging and 10,257+ input limits.
- Actual controller race cases: same-path late old-Host reply, new request not
  cleared by old finally, slow poll coalescing, source failure and hidden/new view.
- Local Computer Use: actual isolated Host with 131 synthetic records, 50/50/31
  pages, source filters, explicit refresh, 390px light and dark / 320px light.
  This is browser viewport testing, not physical iOS/background-recovery proof.
  The final isolated preview also verified populated-search Escape closes in
  one press and restores focus, and completed Codex output has read-only input
  with Send disabled. Restarting only the owned preview avoided old SW caches.
- CI-only `scripts/conversation-browser-cases.mjs` adds 1440/390/320 cases to
  the established rolling UI workflow: local-only requests, page limits, same
  name across six sources, stale recovery, row preservation, modal focus and
  opening a completed Codex task without launching a model. A workflow added
  here is not a passed CI result until the exact commit's run finishes.

Reproduce the owned fixture with `node scripts/agent-identity-preview.mjs
--catalog-stress`; Ctrl-C cleans up only that preview and its synthetic HOME.
The new copy has explicit translations in all 11 existing interface languages.

## Still open (not renamed to done)

1. Source-level opt-in, incrementally discovering Claude/Codex/OpenCode/Grok
   native conversations that were not created inside Stepsemble. An installed
   connector alone provides no complete native conversation inventory.
2. Reviewed native source formats/API versions, stable title/ID/branch handling,
   bounded metadata enrichment, source revocation and reader-platform gates.
3. Full native history, native resume, approval ACKs, durable journal recovery
   and one-writer rules for those connectors. Terminal tails are not substitutes.
4. Candidate release/rolling-device verification after the required gates;
   this change does not restart production, enable private sources or alter the soak.
5. Physical-device testing, accessibility text-size testing and measured
   browser performance thresholds; translations still benefit from native-speaker review.
