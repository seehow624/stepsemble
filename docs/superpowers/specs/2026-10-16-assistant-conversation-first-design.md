# Assistant：對話優先的手機介面（A 方案）

日期：2026-10-16

狀態：實作與自動化驗證已完成；使用者已追加授權提交、合併及發布。

開發分支：`feature/assistant-conversation-first`
基準：本機 `master` 的 `464e871`（3.9.4）；開始實作及發布前都要重驗，不把這裡的版本當成固定最新版。

## 1. 目標與範圍

把 Assistant 做成手機上以「找 Bot、讀回覆、輸入訊息」為主的聊天介面，而不是縮小的設定面板。
這次一併處理三個連在一起的問題：

1. 歷史對話裡的寬表格讓整個對話區可以橫向捲動。
2. Bot 內沒有自己的瀏覽器歷史，手機返回直接跳到 Workspace。
3. 首頁、歷史列表與對話頁缺乏一致的層級，工具紀錄和管理操作搶走閱讀空間。

此次以前端調整為主，不更換 Hermes 協定、不搬移對話、不改模型與登入憑證，不停用現有功能。
伺服器只補上既有唯讀 `session.title` 的標題，以及歷史列表的原始 `nextOffset`；不增加路由或 Hermes 方法。
登入導覽、Hermes 控制台與 Workspace 的 Agent 工作區不另作設計重整，只維持相容。
本次「選 A」不是發布授權；完成後先回報驗證與預覽，發布另確認。

## 2. 已重現的根因

以相同 3.9.4 程式、假 Hermes 和 393×852 的手機視窗重現：

- 一般段落：對話區 `clientWidth=393`、`scrollWidth=393`。
- 12 欄表格：對話區 `clientWidth=393`、`scrollWidth=9355`。
  設 `scrollLeft=200` 後，使用者訊息的左邊由 16px 移到 −184px，而頁首不動。
- 原因：Assistant 的 Markdown 直接輸出 `<table>`，卻沿用共用樣式的 `width:max-content`，
  沒有像 `public/app.js` 的 `enhanceTables()` 一樣包成局部捲動容器。
- 從 Workspace 進 Assistant → Bot → 其他對話 → 一筆歷史，呼叫瀏覽器返回後的路徑是 `/workspace.html`。
  原因：`assistant.js` 只呼叫 `history.replaceState()`，沒有建立內部路由項目，也沒有處理 `popstate`。
- 一個問題、7 筆工具訊息、一個回答，現有 `fromHistory()` 會變成 8 個 assistant 區塊，
  其中 7 個沒有文字回答。這解釋了歷史頁一排排工具標籤和大片空白的觀感。

上述診斷未讀取真實 Hermes 對話，未呼叫模型。

## 3. 核定的視覺方向

使用者在互動稿及對話中選擇 **A：對話優先**，不採 B 的用途卡片＋固定三分頁。

A 的原則：

- 不加裝飾性星形圖標、假狀態、儀表板或大型空白展示區。
- 首頁用一列一個 Bot 的列表；保留名稱、簡短預覽、時間和需要回覆的提示。
- 手機對話內不再顯示「工作區｜助理」全域切換，也不顯示原本四個長分頁。
- 歷史從對話右上角開啟；設定與例行工作放在有名稱的更多選單裡。
- 沿用 Stepsemble 的深／淺主題變數、文字縮放與減少動態設定，不建立另一套獨立色盤。
- 頭像保留使用者設定；沒有圖片時是清楚的單色縮寫，不再加裝飾。
- 互動稿的 Mac Mini、Bot 名稱、訊息、時間均為示意；正式頁用目前所選機器與 Hermes 回傳資料。

## 4. 三個主要畫面

### 4.1 Bot 首頁

上到下：

1. 小型「工作區｜助理」切換與「新增」。
2. 「助理」標題、Hermes 所在電腦名稱。多機時仍可切換。
3. 搜尋欄：搜尋已載入的 Bot／群組名稱、說明和預覽，不呼叫模型。
4. Bot 列表：頭像、名稱、最新對話預覽、時間；需要回覆時有數字與明確文字提示。
5. 群組列表及「新增群組」。
6. 「所有例行工作」與「管理 Bot」入口。

管理功能仍能進入 Bot 設定、顯示／隱藏已隱藏的 Bot、建立與刪除 Bot；不必把所有管理按鈕放在每列上。
頁面上只顯示 API 能證明的資訊，不替每個 Bot 虛構「在線」或「執行中」狀態。
連線失敗要顯示離線／重試，不留下綠色的假成功狀態。

寬螢幕保留左側列表與右側對話的雙欄；手機一次只顯示一個主要畫面。

### 4.2 對話頁

頁首固定：

- 左：「返回助理」操作，目的地是 Bot 首頁；極窄螢幕只留返回箭頭以保住 Bot 名稱，可及名稱仍是「返回助理」。
- 中：Bot 頭像、名稱；副標是目前的 Bot Chat 或歷史對話標題。
- 右：「歷史」與「更多選項」。

移除原有 `Chat / Other conversations / Routines / Settings` 橫向分頁列。
更多選項可到這個 Bot 的例行工作與設定；功能沒有刪掉，只是離開主要閱讀區。

訊息：

- 使用者訊息靠右、Bot 回覆靠左；不替每個工具訊息產生一個空回答和頭像。
- Bot 名稱只在需要分辨發言者時重複，例如群組；避免每個小片段重複畫面元素。
- 思考／工具步驟合併成一個可展開的摘要，保留順序、名稱與可用的詳細內容。
  未完成的步驟不標成完成；失敗與需要使用者回覆的訊息不埋進摘要。
- 核准、提問、sudo 與 secret 卡片維持直接可見，仍由使用者明確回覆。
- 使用者正在往上讀時，不因新 token 或工具事件把畫面強拉到底部。

輸入區固定在底部，保留附件、停止、送出；手機鍵盤與安全區不得擠掉按鈕。
切換路由不等於中斷 Hermes；草稿與尚未送出的附件只保留於當前頁面的記憶體，不寫進 URL、瀏覽器歷史或持久儲存。

### 4.3 歷史列表

由對話頁開啟一個可關閉的歷史面板：

- 手機是底部上拉面板；桌面在對話欄內顯示，不遮住整個工作區。
- 標題「歷史對話」，副標指明目前是哪個 Bot。
- 搜尋保留既有的伺服器搜尋與分頁，不縮減為只能搜已載入的幾筆。
- 依最後活動日期分組；每列為標題、短預覽、來源（例如 Telegram／例行工作）與時間。
- 重新命名、刪除收在該列的更多操作裡；刪除仍需確認，點進對話不觸發任何修改。
- 選一筆歷史就收起面板，閱讀該筆內容；再次開啟時保留同一個 Bot 的搜尋條件與捲動位置。
- 空白搜尋結果、載入、離線與重試要分得清楚，不把錯誤顯示成「沒有對話」。

## 5. 返回、網址與手勢契約

這些是實作與驗收規則，不只是假圖的效果。

| 畫面 | 返回目的地 |
|---|---|
| Bot 對話（永久 Bot Chat 或歷史對話） | Assistant Bot 首頁 |
| 群組對話 | Assistant Bot 首頁 |
| 對話上的歷史面板／更多選單 | 收起面板，留下原對話 |
| 從 Bot 開啟的設定／例行工作 | 該 Bot 的對話 |
| Bot 首頁 | 才允許由瀏覽器返回原本的外部頁面，例如 Workspace |

畫面左上返回鍵、瀏覽器返回／前進、iPhone 原生左緣右滑，使用同一套路由資料，不各自寫一套顯示／隱藏邏輯。
不攔截整頁 `touchmove`，不把表格、程式碼或文字選取的橫向操作誤判為返回。

路由實作限制：

- 保留既有 `/assistant.html?bot=...&session=...` 與 `?view=console` 入口。
- 從推播或外部網址直接進對話時，也要先有一個 Assistant 首頁的返回落點。
- 重新整理不重複插入首頁／對話歷史項目。
- 選歷史時替換同一層的對話，而不是累積「對話 → 歷史 → 另一個對話」的返回鏈；
  選完後一次返回仍是 Bot 首頁，不是上一筆 Bot Chat，更不是 Workspace。
- 導覽、登入重新整理、切換機器、後端重新同步，不得插入假的使用者導覽紀錄。
- 前進時還原網址指定的 Bot／群組／對話，不能用過時的全域 `chat` 指向別筆。
- 歷史 state 只放機器、profile、session、畫面、面板與必要的版本識別；
  不放對話內容、附件、密碼、核准答案。
- 快速點擊切換時，過期的讀取結果不覆蓋新的路由。不要因此取消已送給 Hermes 的工作。
- Hermes 控制台從 Stepsemble 設定進入時，仍返回原本設定；不強迫它走 Bot 首頁。

## 6. 寬內容契約

不能只把整個頁面設 `overflow-x:hidden` 然後裁掉內容。

1. 使用者、Bot、群組及歷史對話使用同一個受約束的閱讀容器。
2. Markdown 表格以與主 App 一致的 `.md-table`／`.md-table-scroll`／`.md-cell` 包裝。
   每欄保留可閱讀寬度，超寬時只捲動表格。
3. 程式碼只在自己的 `pre` 區域橫向捲動。
4. 長網址、路徑、行內程式碼與附件名稱可換行；圖片依回覆寬度縮放，不靠裁切藏掉。
5. DOMPurify 繼續清理 Markdown，外部連結維持安全的新視窗屬性，不把原始 HTML 直接信任為介面。
6. 處理串流重繪、歷史恢復與切換機器時，都要維持局部捲動範圍。
7. 驗證容器實際 `scrollWidth <= clientWidth + 1`，並嘗試改變 `scrollLeft`；
   同時證明表格／程式碼仍能在自己的容器裡橫滑，不能把它們也鎖死。

## 7. 前端邊界

| 單位 | 職責 |
|---|---|
| `assistant-navigation.js`（新增） | 解析／驗證路由、建立返回層級、處理 popstate；不讀寫 Hermes |
| `assistant-content.js`（新增） | 受限寬度的 Markdown、表格與程式碼增強；重用既有樣式契約，不依賴主 App 的整個 `app.js` |
| `assistant-history.js`（新增） | 搜尋、分頁、日期分組、更多操作與面板生命週期 |
| `assistant-model.js` | 歷史工具訊息分組等純資料轉換，Node 測試可直接驗證 |
| `assistant.js` | 連線、串流與各畫面的組裝；逐步委派路由、內容、歷史，不做無關重構 |
| `assistant.css` | A 方案版面、內容寬度、安全區與響應式規則 |
| `assistant-i18n.js` | 所有新介面文字補齊既有 11 種語言 |
| 原有 routines／groups／manage 模組 | 沿用原功能，透過新的入口與返回規則接入 |

前端和伺服器的界線不變：只經 Stepsemble 的 `/api/assistant/*`，跨機器沿用 `/r/<id>`。
不在這個任務改 Hermes 身分、權限、登入方式或保存對話的策略。

## 8. 可及性與操作

- 手機主要操作、返回、歷史、更多與輸入區控制，點擊範圍至少 44×44 CSS px。
- 圖示按鈕有明確的可及名稱；沒有意義的裝飾圖標不加入。
- 歷史與更多面板使用適當的 dialog／面板語意；打開時移入焦點、限制鍵盤焦點，關閉還原至開啟按鈕。
- Escape、可見的關閉鍵與瀏覽器返回行為一致。
- 文字縮放至 150% 仍可閱讀與操作，不讓分頁或固定高度把文字裁掉。
- 深色、淺色和減少動態均依既有偏好；錯誤、未讀與待回覆不只靠顏色區分。

## 9. 測試與完成條件

### 純函式與路由測試

- 路由解析、非法參數、直接深連結、重載、返回／前進、機器切換。
- 從歷史選取後保持同一層對話，設定與面板正常返回。
- 7 筆連續工具紀錄不變成 7 個空回答；使用者／回答順序不變，工具詳細內容不丟失。

### 假 Hermes 瀏覽器測試

- 一般文字、長網址、長檔名、超寬表格、程式碼、大圖片、核准卡。
- 真正測 `page.goBack()`／`page.goForward()`，不是只點畫面返回鍵。
- 從 Workspace 進入及外部深連結進入：對話返回先到 Assistant 列表。
- 歷史面板返回先關面板；選歷史後一次返回到 Bot 首頁。
- 復原搜尋、列表捲動、串流中切換、快速連點與過期讀取結果。
- 深／淺主題；320、393、414px 手機、手機橫向及 1440px 桌面；繁中、英文與長標籤語系。
- 對話、列表、歷史都截圖檢視；另量測寬度與點擊範圍，不以「截圖看起來沒事」取代斷言。
- 不讀取真實 Hermes 對話，不送模型請求，不花模型額度。

### 既有關卡

`npm run check`、`npm run version:check`、`npm run check:client`、`npm test`、`npm run test:rolling`。
完整單元測試使用隔離的 HOME／設定驗證，避免把這台機器的個人 Claude 設定當作測試輸入。
任何失敗必須分辨與說明，不預先宣稱 CI 一定會過。

Playwright 的瀏覽器返回可以驗證網頁歷史邏輯，但不等於 iPhone 主畫面 App 的原生邊緣手勢已通過。
這項實機差異要明確列出，保留手機確認步驟，不能宣稱已在實機驗證。

## 10. 實作順序與審查

1. 先把已重現的橫向溢出及返回錯層寫成失敗的測試。
2. 完成局部捲動、歷史工具分組和路由，確保正確性。
3. 套用 A 的對話頁與歷史面板，再整理 Bot 首頁與群組入口。
4. 接回例行工作、設定、管理、登入導覽及原有推播。
5. 補齊多語、可及性、響應式與回歸，提供新版畫面／預覽。
6. 依使用者回饋修整後，再另取得發布確認；不因以前的發布授權直接推這一版。

## 11. 不包含

- 新模型、API 用量策略、Hermes 升級或新權限。
- 自動核准或替使用者執行真機工作。
- 讀取或上傳使用者的真實對話來製作展示。
- Workspace Agent Session 頁面重做。
- 僅為過關而刪掉舊功能、跳過失敗測試或無限延長測試逾時。
